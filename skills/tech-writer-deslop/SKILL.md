# 去 AI 味（中英双语）

## 这个 skill 做什么

给一篇已经写好的文稿挑出 AI 味，出**诊断**、**打分**、按诊断**改稿**。中文和英文各有一套模式表，脚本自动按语种切换。

**和 `tech-writer` 的分工**：`tech-writer` 管「读者读不读得懂」，这个 skill 管「读起来像不像人写的」。两件事互不覆盖——一篇结构清晰、术语都解释过的好文档，照样可以满屏加粗、句句「不仅仅是…更是…」。先用 `tech-writer` 写清楚，再用这个 skill 去味；顺序反了会白改一遍。

## 唯一的判据

一句话该不该留，只问一个问题：**它是否携带只有作者知道的具体信息？**

AI 味的本质不是用词土，是**空转**——语法完整、看着像结论，但把它删掉，读者的认知没有任何损失。「这背后有其深层的原因」删掉不损失什么；「这背后的原因是配额按项目算、不按 key 算」删掉就少了一条事实。

所有规则都是这一条的推论。记住这条，遇到规则表没收录的新句式你也能自己判断。

## 四种用法

用户说什么，决定做到哪一步。默认走「审稿」，别自动改稿——**改稿会顺手改掉事实**，作者必须有机会先看诊断。

| 模式 | 用户说 | 你交付什么 |
|---|---|---|
| **审稿**（默认） | 看看这篇 / 有没有 AI 味 / 帮我审一下 | 诊断报告 + 五维打分，**不动原文** |
| **改稿** | 改一下 / 去掉这些 | 逐处改写，给「原句 → 改句」对照 |
| **随写随查** | 写作过程中 | 把核心规则当约束用，交稿前跑一遍脚本 |
| **复审** | 有人已经去过一遍味，帮我看改得对不对 | 只审不改：出裁决 + 回炉清单，交回改写方 |

用户只丢来一篇文稿没说要干什么，先做审稿，末尾问一句要不要按诊断改。

走复审模式时，读 [references/review-mode.md](references/review-mode.md) 拿五个检查项。它是**只审不改**：同一个人既改稿又给自己打分，那个分数不是评审结论，是自我印象。

## 什么时候别用这个 skill

- **五维打分低于 35/50**：那是结构问题，该重写而不是逐句去味，用 `tech-writer` 重新搭。
- **纯 Markdown 格式化**（缩进、列表符号、表格对齐）：那是排版工具的活。
- **要求扩写、补内容、加例子**：这个 skill 只让文字变少或不变，不产出新内容。
- **原文意图不明到无法判断具体性升降**：判断不了就问作者，别猜着改。
- **代码注释与提交信息**：规则是按散文校准的，套到代码上会误伤。

## 工作流

### 第 0 步：跑脚本，别靠肉眼

```bash
python3 {baseDir}/scripts/scan.py 文件.md
```

`{baseDir}` 是本 SKILL.md 所在目录。常用参数：`--only red` 只看红线，`--json` 给程序用，`--max-per-rule 5` 控制每条规则列几处。

脚本自动排除代码块、行内代码、URL、frontmatter，所以行号可以直接跳过去。它按 CJK 占比自动选中文还是英文规则表。

**为什么必须跑脚本**：满屏加粗这类问题只在全文统计里才看得见。逐句读的时候，每一处加粗单看都站得住；只有算出「92% 的段落都有加粗」，才知道加粗已经不表示重点了。人眼和模型都做不了这种统计。

脚本只找嫌疑，不定罪。正则分不清「这不是坐标系，每条轴可以多选」（作者在划类比边界，该留）和「这不是技术问题，而是管理问题」（假反转，该删）。**定罪是你的活。**

### 第 1 步：先看密度，它比用词更能暴露 AI 味

拿真实中文技术文档实测过：一批写得相当好的文档，逐条规则几乎零红线，但**加粗字占比 8%–19%、含加粗段落 63%–93%**。也就是说，这类稿子的 AI 味几乎全在排版上，不在用词上。

先处理超标的密度项，再看逐条命中。顺序反了会花大力气抠副词，而满屏加粗一处没动。

| 指标 | 上限 | 超标意味着 |
|---|---|---|
| 加粗字占比 | 10% | 加粗过一成，读者的眼睛没有落点 |
| 含加粗段落 | 85% | 段段都加粗，加粗不再标记重点 |
| 破折号 —— | 2.5/千字 | 破折号顶替了本该由句号和逗号承担的分句 |
| emoji | 0.3/千字 | emoji 小标题是 AI 排版最明显的指纹 |
| 感叹号 | 0.5/千字 | 技术文档里几乎总是虚假热情 |
| 连接词 | 8/千字 | 因此/然而/此外 密集，说明段间逻辑是贴上去的 |
| 三项排比 | 2/千字 | 三项并列朗朗上口，所以 AI 特别爱用 |

**过线即停。** 阈值是一条线，不是一个越低越好的方向：只动超标项，达标项保持原样，超标项一跨回线内就收手。继续压下去，砍的不再是 AI 味，而是作者的正常表达。实测里见过一次：含加粗段落原本 82.5%（本来就达标），改稿还是把它压到 60.8%；那次没造成损害，因为功能性加粗都保住了，但那是运气不是方法。加粗降到 8% 就够了，不必追到 5%。

**减加粗最容易改错，先记住哪些必须留。** 实测过一次失败：两份改稿都把加粗从 17.4% 降到 8%，数字一样，砍的东西完全相反——一份砍装饰，一份砍功能。同样的指标，一个保住了可用性，一个只保住了数字。

**必须留的四类**：

1. **术语首次出现。** 尤其当作者说过「后文会反复引用它」——那个加粗是全文的锚点，去掉之后读者回头找不到定义在哪。也包括作者明说「这些名字是给你当搜索词用的」那类。
2. **可操作的指令和判据。** 「务必看中文榜单，别只看英文分数」「文件路径 + 函数名而不给行号」——读者要照着做的那一句。
3. **决策清单里的条件。** 「资料类型**单一**」「**就你一个人维护**」——跳读时要扫的判据。
4. **构成对比的那个词。** 「关键词只匹配字面；向量抓的是**意思**」——去掉加粗，对比就散了。

**该砍的是**：整句加粗（「**这对中文尤其明显**」）、已经介绍过的术语再次加粗、纯粹提示「这句是重点」的加粗。重点该由位置和论证承担。

判据一句话：**问每一处「读者跳读时必须看到它吗」**，不是「这句重要吗」——重要的句子太多了，加粗筛的是必须被眼睛捕捉到的那几处。目标是让至少三成段落保持素面，剩下的加粗才有对比度。

**破折号也有两种正当用法，别机械清零。** 实测里有一份改稿砍到 0.7‰，把这两种一起清了，读出了病句：

- **成对插入语**：「500 篇资料——文章、论文、会议记录——想让 AI 回答问题」。成对破折号做同位语插入是标准中文用法，改成括号是风格选择，不是去 AI 味。
- **术语—定义**：「**局部查询(Local)**——从问题命中的实体出发」。删掉破折号会变成「局部查询(Local)从问题命中的实体出发」，读成病句。

该改的是**单个破折号顶替逗号或句号**那种，一句话里冒出一个 —— 只为了停顿一下。同样过线即停：回到 2.5/千字以内就收手，再砍就开始动上面这两种正当用法。

**全文统一的约定符号不算 AI 味**。比如固定用 `📌` 标「参考实现旁注」、`⚠` 标风险，是有意的阅读约定，脚本会报 emoji 超标，你要判断出来并放过它。区别在于：装饰性 emoji 每个不同（🚀✨💡 换着用），约定性符号全文只有一两种、含义固定。

### 第 2 步：逐条判断，先过豁免关

命中不等于该改。脚本报的每一条 amber 都要先过这三道豁免闸：

1. **技术术语豁免。** 判据：这个词在本文里有确定的技术指称吗？「心智模型」有，「抢占用户心智」没有。
2. **纠正真误解豁免。** 判据：X 是读者真的可能相信的东西吗？是就留，是作者临时立的靶子就删。
3. **精确性豁免。** 判据：删掉之后这句话变强了吗？变强了而事实不支持那么强，就留着。

三道闸的判例表和边界情况在 [zh-patterns.md](references/zh-patterns.md)（对应 zh-jargon / zh-contrast / zh-hedge）和 [en-patterns.md](references/en-patterns.md)。拿不准就查，别凭印象放过或砍掉。

过完豁免还站得住的，才进诊断清单。

### 第 3 步：改稿要可核对

技术文档改稿最大的风险不是改不动，是**改的时候顺手改掉事实**——把「约 300 字」写成「300 字」，把「多数实现」写成「所有实现」。所以：

- **逐处给「原句 → 改句」对照，不要整篇重写后交付。** 整篇重写让作者无法核对，事实漂移会静默通过。
- **只动措辞，不动断言。** 数字、路径、版本号、条件限定词（约/多数/通常/在 X 情况下）原样保留。要改断言，单独提出来问。
- **别降级。这是红线。** 「降级」＝把具体换成空泛，也就是亲手制造一句空转。现有规则防的是「原文本来就空泛」，防不住「改稿把它改空了」，而后者更隐蔽，因为它以「精简」的名义发生。实测里见过这样一处：原文「叫『轴』只取『彼此独立』这一层意思，不是坐标系——每条轴上都可以多选」被改成「这个叫法有个边界，讲完三条轴马上说」。短了一半，但原文说清了边界**是什么**，改稿只说「有个边界」。**每改一处问一次：具体性升了还是降了？降了就回退，哪怕更短。**

- **别把重复当冗余删。** 同一个结论在导读、展开、小结三处各出现一次，通常是有意的——那是概括层和细节层在对账，让读者在不同深度都能接住。判据：三处的**读者位置**一样吗？位置不同（还没读 / 正在读 / 读完了）就不是重复。

- **指定了范围就只动那个范围。** 用户说「看看第 3 节」，就只诊断第 3 节。文稿场景比代码更危险：改动散在全篇，作者不容易发现你越界了。范围外发现的问题，列出来问一句，不要静默扩大。

- **删不掉就先标出来。** 有些空话删掉会留下逻辑断口，说明那里本该有内容而作者没写。这种不要硬删，标注「这里需要补一个具体例子」交回作者。

### 第 4 步：复扫对账

改完重跑一遍脚本，对比改前改后的数字。这一步不是形式：**「我改过了」和「指标真的降下来了」是两件事**，前者靠印象，后者靠数字。密度项没降下来，说明改的地方不是问题所在。

## 核心规则（中英通用）

八条，按重要性排。**这些是审查提示，不是绝对禁令**：作者有明确理由的选择要留下来，最终判断始终回到「唯一的判据」那一条。中文特有的细则见 [references/zh-patterns.md](references/zh-patterns.md)，英文见 [references/en-patterns.md](references/en-patterns.md)，改写示例见 [references/examples.md](references/examples.md)。

1. **删掉空转句。** 宣布重要（「值得注意的是」）、宣布深刻（「这背后有深层原因」）、宣布要开始讲（「让我们来看看」）、宣布讲完了（「总而言之」）——全删。它们描述文章自己，不描述世界。

2. **拆掉假反转。** 「不是 X，而是 Y」「不仅仅是 X，更是 Y」「与其说 X，不如说 Y」——先过豁免 2，是靶子就删前半句，直接说 Y。

3. **点出人。** 数据不会告诉我们什么，市场不会奖励谁，架构不会要求什么。这些句子把人删掉了，而读者最想知道的恰好是谁做的决定。找不到具体的人，就用「你」把读者放进那个位置。

4. **把名词还原成动词。** 「对配置进行调整」→「改配置」；「做出技术选型的决定」→「选了 X」。中文动词天生能直接带宾语，套上「进行/实现/加以」是从英文语法搬来的空壳。英文对应的是被动语态：找出施动者，放到句首。

5. **具体化。** 「具有重要意义」→ 具体什么意义。「性能有提升」→ 提升多少、在什么负载下。写不出具体的，说明这句话本来就没内容，删掉。

6. **控制排版密度。** 见第 1 步的表。加粗、破折号、emoji、感叹号都是有限资源，用得越多每一次越不值钱。

7. **让节奏不整齐。** 连续三句长度接近就断一句。每段都以短句金句收尾就换掉几个。AI 的节奏是匀速的，人写东西有快有慢。

8. **信任读者。** 不预告结构（「本文接下来将……」），不铺垫（「想必你已经猜到」），不免责（「以上仅供参考」）。真有不确定的地方，写在那个具体断言旁边，说清哪一条不确定、怎么自己验证。

## 五维打分

审稿模式要给分。每项 1–10，附一句依据，不要只给数字。

| 维度 | 问什么 |
|---|---|
| 信息密度 | 随手删一句，读者会损失信息吗？空转句占多少？ |
| 直接性 | 是在陈述，还是在宣布自己要陈述？ |
| 具体性 | 断言都落到了具体的人、数、条件上吗？ |
| 节奏 | 长短句有变化，还是匀速？ |
| 排版克制 | 加粗/破折号/emoji 是有限使用，还是满屏？ |

**低于 35/50 建议重写而不是逐句改**——分这么低通常说明问题在结构，逐句改会把力气花在表面。

打分要对着证据。「直接性 6 分」后面要能跟一句「§3 和 §5 开头都是『值得注意的是』」。给不出证据的分数是自己在产生 AI 味。

## 交付格式

审稿模式按这个结构出报告：

```markdown
## 总评
[两三句话说清主要问题在哪一层：排版 / 句式 / 空转。给出总分 X/50。]

## 密度指标
[脚本输出的表，标出超标项和它意味着什么]

## 逐处诊断
### [问题类型]（红线/酌情） — N 处
- L46 `原句片段` → 建议：[怎么改]
- ...

## 已豁免
[命中但判断为合法的，逐条说理由。理由要指向这篇文稿的具体内容，
不是复述通则。]

## 剩余风险
[和「已豁免」不同：豁免是「我看过、判断该留」，这一节是「我没把握 / 没覆盖到 /
需要你自己定」。哪几节只抽读没通读、哪处自己也不确定、哪个断言需要作者核实。
写「无」可以，省掉这一节不行。]

## 五维打分
[表格 + 每项一句依据]
```

**脚本报的每一处命中，都必须在报告里有归属**：进「逐处诊断」、进「已豁免」，或者进「剩余风险」。三节之外不许有漏项。报告写完对一遍数：三节的条数加起来，应该等于脚本报的命中数（密度项按项算）。对不上就是漏了，不是「不重要所以没写」。

这条判据是「已豁免」和「剩余风险」两节存在的理由：前者告诉作者「我看过、有意放过」，后者告诉作者「这块你得自己看」。少了任何一节，漏项和放过就分不开了。

改稿模式在此基础上加一节「原句 → 改句」对照。

## 改完通读一遍

这个 skill 最常见的失败不是漏掉 AI 味，是**为了守规则把句子改别扭**。三种典型：

- 副词删到句子读不顺。过线即停，留着比删干净好。
- 为了避开「不是 X 而是 Y」绕出一个更长的句子，是把一种毛病换成另一种。
- 加粗一次砍光，重点全没了。

规则表里没有的句式，用「唯一的判据」自己判，不要因为它不在表里就放过。

**通读的判据只有一条：读起来比原文更硬、更绕吗？** 是就是改坏了，回退。目标是让文字像一个懂行的人自然写出来的，不是让它通过一份检查表。
