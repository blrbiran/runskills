# 复审模式：审另一次去 slop 的结果

## 为什么要把写和审分开

改稿的人已经为每一处改动想好了理由，所以他最不容易看见的，恰好是自己改错的地方。复审只做一件事：审改写方交回来的结果，**不动手改**。

出裁决和回炉清单，交回改写方。**不要自己顺手改掉再批准通过**——那等于又把写和审合并回一个人。

## 先自己跑脚本

改前、改后两份各跑一次 `scripts/scan.py`。指标对账用**你自己跑出来的数**，不用改写方给的——「我改过了」和「指标真的降下来了」是两件事，而给出前一句的正是被审的那个人。

## 五个检查项

1. **该留的有没有被删。** 术语首现加粗、成对破折号、承载精确含义的限定词（基本上 / 理论上 / 多数）、纠正真误解的「不是 X 而是 Y」。四类的判据见 SKILL.md 第 1 步和第 2 步。

2. **有没有压过线。** 「过线即停」有没有被当成「越低越好」？两个问题：超标项现在降到阈值以下多远，本来就达标的项被动过吗。

3. **事实有没有静默漂移。** 数字、路径、版本号、条件限定词（约 / 多数 / 通常 / 在 X 情况下）逐项比对改前改后。这一项要真的对着两份文本比，不能凭改写方的说明。

4. **豁免理由站不站得住。** 「已豁免」那一节写的是真判断，还是为了少改找的借口。判据：理由里有没有指向这篇文稿的具体内容。「术语首现要留」是通则，「第 2 节把『局部查询』定义在这里、第 5 节还要引用」才是判断。

5. **有没有降级。** 逐处对照「原句 → 改句」，问具体性升了还是降了。把「不是坐标系，每条轴都可以多选」改成「这个叫法有个边界」就是降级：短了，但原文说清了边界是什么，改稿只说「有个边界」。

## 裁决怎么写

```markdown
## 裁决
[通过 / 部分回炉 / 整体回炉。一句话说清主要依据。]

## 回炉清单
- L46 改写方把 `原句` 改成 `改句` —— 降级：原文给了具体条件，改稿只说「有条件」。建议回退。
- ...

## 指标对账
[改前 → 改后，标出哪些是必要的下降、哪些是压过了线]

## 我没覆盖到的
[抽读了哪几节、哪几节没通读。写「全文通读」可以，省掉这一节不行。]
```
