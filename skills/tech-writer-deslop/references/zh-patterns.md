# 中文 AI 味模式表

规则 ID 和 `scripts/scan.py` 里的一致，脚本报了哪条就查哪条。

**这份文件只放脚本给不了的东西**：判例、豁免、边界。每条规则「为什么是 AI 味」和「怎么改」由脚本随命中一起打印，不在这里重复。

**红线**＝几乎总是 AI 味，命中就动手。**酌情**＝合法用法和 AI 味长得一样，必须看语境。

---

## zh-opener 清嗓子开场（红线）

在当今…的时代 / 随着…的不断发展 / 众所周知 / 不得不说 / 说到 X 就不得不提 /
让我们一起来看看 / 首先要明确的是 / 在正式开始之前 / 话不多说

删完读一遍开头。如果第一句就是实质内容，对了。

---

## zh-emphasis 强调废话（红线）

值得注意的是 / 需要注意的是 / 需要指出的是 / 值得一提的是 / 划重点 / 敲黑板 /
重要的事情说三遍 / 请记住这一点 / 这一点非常重要 / 不难看出 / 显而易见 / 毋庸置疑

**豁免**：「**最**值得注意的是」「**尤其**需要注意的是」是在一组东西里做排序，有实义，留。脚本已经排除这两种前缀。

---

## zh-wrapup 万能收尾与拔高（红线）

总而言之 / 综上所述 / 总的来说 / 概括来说 / 由此可见 / 不难发现 /
希望本文对你有帮助 / 未来可期 / 让我们共同期待 / 任重道远 / 值得我们深思 /
这或许就是 X 的魅力（意义 / 智慧 / 哲学）

AI 收尾的固定动作是「复述一遍 + 往上拔一层」。读者刚读完不需要复述，拔高那一层通常是空的：它把具体结论换成一句放到任何文章末尾都成立的话。

文章可以在最后一个实质结论处直接停住。真需要收束，写「所以，如果你要做 X，先做 Y」这种带动作的句子。

---

## zh-contrast 二元对比套路（酌情，假阳性最高）

不是 X，而是 Y / 并非 X，而是 Y / 不仅仅是 X，更是 Y / 与其说 X，不如说 Y /
表面上 X，实际上 Y / X 的本质不是…

**判据只有一条：X 是不是读者真的可能相信的东西。**

| 句子 | 判断 | 为什么 |
|---|---|---|
| 模型不是按「字」来数长度的，而是切成 token | 留 | 读者真会那么以为，这是在拆一个真实误解 |
| GraphRAG 不是用来取代向量 RAG 的，而是补它最弱的一环 | 留 | 「取代」是流传很广的误读 |
| 它不是某个产品的内置功能，而是一份公开的 skill | 留 | 在做分类澄清，读者确实会归错类 |
| 这不是技术问题，而是管理问题 | 改 | 没人主张它纯是技术问题，X 是临时立的靶子 |
| 微服务不仅仅是拆分，更是一种思维方式的转变 | 改 | 「思维方式的转变」本身也是空话，双重毛病 |

删掉 X 之后 Y 显得平淡——那正说明 Y 本来就平淡，是 X 在给它撑场面。这种要两头都换成具体内容，不是简单删前半句。

---

## zh-vague 空泛判断（红线）

具有重要意义 / 起到了关键作用 / 意义重大 / 影响深远 / 背后有其深层的原因 /
本质上是一种 X / 存在一定的问题

这类句子语法完整、看起来像结论，所以最容易蒙混过关。改法是把具体的东西写出来：

- 「配额设计具有重要意义」→「配额按项目算而不按 key 算，所以一个项目里多开几个 key 分不到更多量」
- 「性能有明显提升」→「同样 500 篇语料，建索引从 40 分钟降到 9 分钟」

写不出具体的，说明这句话本来就没内容，删。

---

## zh-jargon 互联网黑话（酌情）

赋能 / 抓手 / 拉通 / 颗粒度 / 对齐颗粒度 / 用户心智 / 抢占心智 / 业务闭环 /
生态闭环 / 护城河 / 组合拳 / 打法 / 生态位 / 降维打击 / 底层逻辑 / 价值主张 /
全链路 / 数字化转型 / 提升体感 / 做厚 / 长期主义

**豁免——技术术语不是黑话**。这一条假阳性率很高，务必先判断：

| 词 | 技术语境（留） | 黑话语境（改） |
|---|---|---|
| 心智 | 心智模型（mental model）、心智地图 | 抢占用户心智 |
| 闭环 | 反馈闭环（feedback loop）、控制闭环 | 业务闭环、生态闭环 |
| 对齐 | 模型对齐（alignment） | 拉通对齐、对齐颗粒度 |
| 链路 | 调用链路、请求链路 | 全链路赋能 |

判据：这个词在本文里有确定的技术指称吗？有就留。

## zh-europeanized 翻译腔与过度名词化（酌情）

对 X 进行 Y / 进行了优化 / 实现了提升 / 加以处理 / 做出决定 /
当涉及到 / 在某种程度上 / 从某种意义上说 / 基于…的考虑 / 你可能会问 / 有几个原因

- 对配置进行调整 → 改配置
- 进行了一次全面的梳理 → 梳理了一遍
- 实现了检索质量的提升 → 检索更准了 / recall@5 从 32% 涨到 41%
- 做出了技术选型的决定 → 选了 LightRAG

---

## zh-passive 被动滥用（酌情）

被 X 实现 / 被处理 / 受到…的影响 / 由…所决定

**豁免**：施动者确实不重要或不存在时，被动是对的。「这个字段已经被废弃」——谁废弃的无关紧要。

---

## zh-intensifier 纯程度副词（红线）

非常 / 十分 / 极其 / 极为 / 尤为 / 相当地

这一类只加长度不加力量，删掉之后断言强度不变，所以是红线：直接删。

**注意它和 zh-hedge 的分界**：这条收的是纯强化词，删了不损失任何精度；zh-hedge 收的是可能承载精度的限定词，要先过豁免。「非常重要」删「非常」无损，「基本上都能跑」删「基本上」就改变了断言。

---

## zh-hedge 软化词与限定词（酌情）

真正的 / 确实 / 其实 / 基本上 / 某种程度上 / 一定程度上 / 可以说 / 应该说 / 不失为

**豁免——承载精确含义的不能删**：

- 「**基本上**都能跑」≠「都能跑」：前者承认有例外
- 「**理论上**支持」≠「支持」：前者提示没实测
- 「**多数**实现」≠「实现」：前者是有限量化

判据：删掉之后这句话变强了吗？变强了而事实不支持那么强，就留着。纯粹当口头禅的（其实、可以说、应该说）删。

「真正」也常常是实义的：「真正花时间的不是拆，是拆完之后」——这里「真正」在做对比，删掉对比就散了。

---

## zh-agency 虚假主体（酌情）

数据告诉我们 / 技术的发展推动了 / 时代呼唤 / 市场选择了 / 历史证明 /
需求驱动了 / 架构要求必须…

改法：点出人。「数据告诉我们要拆服务」→「我们看完这组延迟数据，决定把结算拆出去」。找不到具体的人，用「你」把读者放进去。

---

## zh-template 三段式模板（酌情）

首先…其次…最后 / 是什么—为什么—怎么做 / 每节末尾都挂一个「小结」

**豁免**：真正的操作步骤该编号，而且必须编号——「第 1 步装依赖，第 2 步改配置」。区别在于：步骤有执行顺序，而「首先…其次…」常常只是并列。

---

## zh-disclaimer AI 式免责（红线）

以上仅供参考 / 具体情况可能有所不同 / 请根据实际情况调整 /
如有错误欢迎指正 / 本文不构成任何建议

真有不确定的断言，写在那一条旁边，说清哪里没核实、怎么自己验证——「这个 0.92 的阈值是配着某个 embedding 模型调的，换模型要自己重测」。

## 靠读发现的结构性 AI 味（正则抓不到）

这几类没有固定词，脚本报不出来，只能通读时看。它们比用词更能暴露 AI，因为作者改词很容易，改结构要重写。

**否定式列举**。「不是框架。不是库。是一套协议。」先否定两三次再给出答案，是欲扬先抑的套路。直接说它是什么。

**戏剧化断句**。「就这样。这就是全部。」「一个函数。三行。」用短句和句号制造分量感。分量该由内容承担，写成完整句子。

**修辞设问**。「那么问题来了」「你可能会问」「想过为什么吗？」——设问之后紧跟自己的答案，说明这个问句只是过门。删掉问句，直接给答案。

**每节都挂小结**。节末的「小结」如果只是把这节内容再说一遍，就是空转。留小结的唯一理由是它给出了正文没给的东西（一张对照表、一条判据）。

**小标题排比**。所有小标题都是同一个句式（都是「X 的 Y」，或者都是四字动宾），读起来像模板填空。小标题该各自说清那一节讲什么，句式整齐不是优点。

**匀速节奏**。每段都以短句金句收尾，段落长度整齐得像排版好的。人写东西有快有慢：讲清一个复杂机制那段自然长，给一个判据那段自然短。
