## 一、讲义腔的提示语

这类句子在**宣布自己要说话**，而不是在说话。删掉提示语，把后面那句顶上来，信息一点不少。

| 书面 | 口语 |
|---|---|
| 关键点在于：X 把 A 和 B 拆开了 | X 干的事就是把 A 和 B 拆开 |
| 这带来一个实际后果：桥接不是无损的 | 翻一道手就会掉东西：桥接不是无损的 |
| 几个字段值得解释 | 有几个字段我多说两句 |
| 需要说明的是，Y 不校验 key | Y 在启动阶段不校验 key |
| 由此可见 / 不难看出 | （删掉，直接说结论） |
| 众所周知 | （删掉；真众所周知就不用写，不是就别赖给读者） |
| 首先要明确 / 接下来我们将 | （删掉，直接讲） |

判据：这句话删掉，读者少了什么信息吗？少不了，就是提示语。

## 二、文档自称与指代

暴露的是「我在交一份文档」而不是「我在跟你讲一件事」。

| 书面 | 口语 |
|---|---|
| 本文 / 本节 / 本篇 | 这篇 / 这一节，或直接删 |
| 本文统一假设它在 `~/x/config.yaml` | 下面我都当它放在 `~/x/config.yaml` |
| 本文还假设你已经装好了 A | 另外我默认你已经装好了 A |
| 笔者 | 我 |
| 上述 / 上文 | 上面那个 / 前面说的 |
| 该字段 / 该文件 | 这个字段 / 这份文件 |
| 业界目前有三种主流形状 | 眼下主流的形状就三种 |
| 如下所示 / 下表所示 | （删掉，图表就在下面，读者看得见） |

「业界」几乎总能直接删掉而不损失信息，值得单独记一笔。

## 三、书面动词与虚词

单看每个都没错，成批出现就把口型从「跟你说」变成「兹通知」。

| 书面 | 口语 |
|---|---|
| 取决于 X | 看 X / 要看 X |
| 关键在于 / 问题在于 | （改成直接陈述） |
| 以 X 为准 | 你看 X / 按 X 来 |
| 即可 | 就行 / 就好 |
| 无需 | 不用 |
| 较为 / 颇为 | 比较 / 挺 |
| 予以保留 / 得以实现 | 留着 / 能做到 |
| 尚未 | 还没 |
| 亦 | 也 |
| 从而使 / 使之 | 让它 / 这样它就 |
| 旨在 | 是为了 |

**这几个不要动**：「必须」「其中」「所以」「因为」都是正常口语，早期版本的正则用 `须` 和 `其(?=中)` 扫出过一片假阳性——一篇稿子 11 处命中里 5 处是「必须」。脚本已经挡掉，你自己判断时也别顺手改。

## 四、名词化的「侧／方面／层面」

画架构图时的切分词，不是开口说话的词。

| 书面 | 口语 |
|---|---|
| 网关侧是我自己在用的 | 网关这部分我自己一直在用 |
| 客户端侧需要配 X | 客户端那边要配 X |
| Z.ai 直连侧能查到 A、B | Z.ai 直连的条目能查到 A、B |
| DeepSeek 侧能查到 C | DeepSeek 那边能查到 C |
| 在性能方面 | 说性能的话，或直接删 |
| 从架构层面看 | 从架构上看 |

## 五、四字成语

成语是压缩过的书面表达，念出来有背诵感。同样的意思口语会说得散一点，往往也更准。

| 书面 | 口语 |
|---|---|
| 混为一谈 | 混在一起 |
| 至关重要 | 特别要紧（或者说清到底怎么要紧） |
| 显而易见 / 不言而喻 | （删掉；真显而易见就不用说） |
| 大同小异 | 差不多 |
| 一劳永逸 | 一次配好以后不用管 |
| 行之有效 | 管用 |
| 屡见不鲜 / 不算罕见 | 不算稀奇事 |

## 六、段落起点

书面连接词起头，读者找不到落点。

| 书面 | 口语 |
|---|---|
| 基于上面的分层，落到实处就是 | 照上面那个分层，落到实处就是 |
| 由于 X，所以 Y | X，所以 Y（「由于」多数时候可以直接删） |
| 对于走不了原生的，A 会做 B | 碰上这种走不了原生的，A 自己做 B |
| 值得注意的是 | （删掉，直接说） |
| 有两个维度容易被混为一谈 | 这里有两个维度，特别容易混在一起 |

起点可以是主语（我／你／我们）、话题词（这里／这套／这一节／碰上这种）或指示代词。

**「我们」可以用**——它是拉着读者一起走。要防的是「大家」。作者认可过的例子：「我们先把分层讲清楚，后面每条配置都从这里推出来」。

顺带一条：「我们先把 X 讲清楚」比「我们先讲清楚 X」顺，中文口语习惯用「把」字把宾语提到前面。

## 七、命中了但该留的

**这一节比词表重要。** 本 skill 最典型的失败是用力过猛。

**裸存在句不是病。**「有两个坑容易踩」「有几个字段我多说两句」在口语里完全成立。「有两个维度容易被混为一谈」难受在成语和「被」字，不在「有」。正则分不出这个差别，所以脚本的 `reg-topicless` 只收书面连接词，存在句交给「无人称段落」指标兜。

**读着顺的「以 X 为准」留着。**「配置里填哪个，以你自己跑出来的结果为准」——这句念出来不别扭，因为「你自己跑出来的结果」已经把人称带进来了。同一个词在「以厂商文档为准」里就该改成「你看厂商自己的文档」。判据永远是念出来，不是查表。

**写给 agent 看的段落不要口语化。** 面向 AI agent 的执行摘要、API 参数说明、报错清单，断言式短句是刻意的——它们要的是无歧义，不是亲切。实测里遇到过一节「给 AI agent 的执行摘要」，整节保持原样没动。

**术语和固定说法不动。**「协议桥接」「虚拟 key」「可选依赖组」是这篇文章自己立的术语，换成大白话读者反而对不上后文。

**「必须」「其中」不是书面腔。** 见第三节。

**严谨限定不要当书面腔删。**「几乎无损」「大概率」「多数情况下」是在诚实地限定断言范围，删掉就是把断言偷偷加强。这条和 deslop 的「精确性豁免」是同一条。

## 八、口语化不等于什么

**不等于加填充词。**「其实呢」「怎么说呢」「说白了」「不得不说」堆上去不是口语化，是另一种腔——而且是更廉价的那种。口语的力气在句子骨架上：有主语、动词直接、一句话说一件事。

**不等于加破折号。** 这是本 skill 最容易犯的错，有实测：把长句改写成「主句——补充说明」之后读着确实像说话了，但破折号从 1.1/千字冲到 3.3，越过 deslop 的 2.5 线。**成对插入语**（「500 篇资料——文章、论文、会议记录——想让 AI 回答问题」）和**术语——定义**两种用法是正当的；该改回标点的是**单个破折号顶替逗号或句号**那种。

**不等于变短。** 语体和长度是两回事。「取决于」换成「要看」省了一个字，「网关侧」换成「网关这部分」多了两个字，都对。要变短是 `wechat-finetune` 的活。

**不等于降低专业度。** 目标是「一个懂行的人自然说出来」，不是「显得热情」。改完通读一遍，比原文更做作就是改坏了。
